# 喵洛阁 App（Tauri v2 多端）实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 给 Nuxt 4 静态博客套上 Tauri v2 外壳，产出 Windows / macOS / Linux / Android / iOS 五端安装包；内容编译期内嵌保证离线可用，并支持不重新发版的内容热更新。

**Architecture:** 注册自定义协议 `app://` 服务 WebView。协议处理器在每次请求时解析「web 根」：优先 `<appData>/web/<activeBuild>/`（已下载的内容包），回退到编译期内嵌资源。内容包（`tar.gz` + `manifest.json`）由部署链路生成到站点的 `/app-dist/`，app 启动后异步比对 `build` 指纹，按需下载、校验、解压到临时目录、原子切换，失败自动回滚。

**Tech Stack:** Nuxt 4.5.2 / Nuxt Content 3 / Tauri 2.x / Rust 1.90+ / `tar` + `flate2` / `reqwest`(rustls) / `sha2` / GitHub Actions

## 0. 执行前置（必读，影响你怎么跑命令）

**本机没有 Rust 工具链。** 已实测：`which cargo rustc` 均无输出；Visual Studio Community 2026 已装但**没有**「使用 C++ 的桌面开发」工作负载，也没有 Windows SDK。

因此本计划中所有 `cargo` 命令**无法在开发者本机执行**，只能在两处执行：

1. **GitHub Actions 的 `check` job**（Task 15 建立）——这是主要的编译反馈通道；
2. 任意装有 Rust 1.90+ 与 MSVC/WebKitGTK/Xcode 的机器。

> **这不是妥协，而是本计划的设计约束**：因为拿不到本地编译反馈，Rust 侧必须刻意保持小面积与少依赖，并且 `check` job 必须最先跑、只跑 `cargo check`（几分钟出结果，不要等整套打包才发现编译错）。

TypeScript / Nuxt / 脚本部分**可以**在本机执行（`pnpm`、`node` 都在）。这是本计划把「可验证的部分」与「只能靠 CI 的部分」分开的原因。

## 1. 冻结接口契约 v1

**以下契约在 Task 1–18 全程不可更改。任何一节如需改动，必须先回来改这一节并在 PR 说明。**

### 1.1 内容包格式：`tar.gz`（不是 zip）

选择理由（实测 + 工程）：本机无 `zip` 命令；Node 用 `node:zlib` 即可生成 tar.gz（不新增依赖）；Rust 侧 `tar::Archive` 与白名单校验配合可彻底避免路径穿越，无需手写 zip-slip 逻辑。

产物落在 `.output/public/app-dist/`：

```
manifest.json
content.tar.gz
```

`manifest.json`：

```json
{
  "schema": 1,
  "build": "8c1f0a2b3d4e5f60",
  "generatedAt": "2026-11-03T03:20:00.000Z",
  "fileCount": 388,
  "totalBytes": 11534336,
  "archive": { "name": "content.tar.gz", "bytes": 3512320, "sha256": "<64 hex>" },
  "files": { "index.html": "<64 hex>", "about/index.html": "<64 hex>" }
}
```

- `build` = `sha256( 按路径升序拼接的 "path\0fileSha256\n" ).hex.slice(0, 16)`
- `files` 的键是相对路径、正斜杠、无前导 `./`
- tar 条目要求：相对路径、正斜杠、**排除 `app-dist/**` 自身**、mtime 固定为 0（保证可复现：同内容必得同 `build`）

### 1.2 Rust 命令面

前端通过 `window.__TAURI__.core.invoke('<name>', { ... })` 调用（参数名用 camelCase，Tauri 自动映射到 Rust 的 snake_case）。

| 命令 | 入参 | 返回 |
| --- | --- | --- |
| `app_status` | — | `{ embeddedBuild, activeBuild, source: 'embedded'\|'downloaded', pendingBuild: string\|null, platform, lastError: string\|null }` |
| `content_check` | `manifestUrl: string` | `{ state:'up-to-date', build }` \| `{ state:'update-available', build, bytes, generatedAt }` \| `{ state:'offline' }` \| `{ state:'error', message }` |
| `content_install` | `manifestUrl: string` | `{ ok:true, build }` \| `{ ok:false, message }` |
| `content_rollback` | — | `{ ok: boolean, build: string }` |

进度事件名 `content://progress`，payload `{ phase: 'download'|'extract', received, total }`。

### 1.3 运行时目录布局

```
<appDataDir>/
  web/
    active.json            { "active": "<build>", "previous": "<build>|null" }
    <build>/               解压后的静态站点（含 index.html）
    <build>.tmp/           解压临时目录（成功后 rename）
```

### 1.4 其他冻结项

- 自定义协议 scheme：**`app`**（Windows/Android 上 Tauri 解析为 `http://app.localhost`，macOS/Linux/iOS 为 `app://localhost`）
- 前端 app 内检测：`'__TAURI__' in window`
- 应用标识：`identifier = top.kemeow.blog`，`productName = 喵洛阁`
- `frontendDist` = `stub`（指向已提交进 git 的 `src-tauri/stub/`）；真正的站点内容走 `bundle.resources` 里的 `seed/`。**不能写官方指引的 `../dist`**：`dist` 未被 git 跟踪，只是本地软链接，CI 上不存在
- CI job 名：`check` / `desktop` / `android` / `ios`

```rust
    pub previous: Option<String>,

/// build 标识只允许 16 位小写十六进制。
/// 这是安全边界：build 会被拼进文件系统路径，必须拒绝 `..`、`/`、`:` 等字符。
pub fn is_valid_build(build: &str) -> bool {
    build.len() == 16
        && build
            .bytes()
            .all(|b| b.is_ascii_digit() || (b'a'..=b'f').contains(&b))
}

fn hex_val(c: u8) -> Option<u8> {
    match c {
        b'0'..=b'9' => Some(c - b'0'),
        b'a'..=b'f' => Some(c - b'a' + 10),
        b'A'..=b'F' => Some(c - b'A' + 10),
        _ => None,
    }
}

fn percent_decode(s: &str) -> String {
    let b = s.as_bytes();
    let mut out: Vec<u8> = Vec::with_capacity(b.len());
    let mut i = 0;
    while i < b.len() {
        if b[i] == b'%' && i + 2 < b.len() {
            if let (Some(h), Some(l)) = (hex_val(b[i + 1]), hex_val(b[i + 2])) {
                out.push(h * 16 + l);
                i += 3;
                continue;
            }
        }
        out.push(b[i]);
        i += 1;
    }
    String::from_utf8_lossy(&out).into_owned()
}

/// 归一化请求路径：去掉查询串/锚点与首斜杠，拒绝 `..` 与 NUL。
/// 返回 `None` 表示这是非法请求，调用方应直接回 404。
pub fn normalize_request_path(raw: &str) -> Option<String> {
    let no_query = raw.split(['?', '#']).next().unwrap_or("");
    let decoded = percent_decode(no_query).replace('\\', "/");
    if decoded.contains('\0') {
        return None;
    }
    let mut parts: Vec<&str> = Vec::new();
    for seg in decoded.split('/') {
        match seg {
            "" | "." => continue,
            ".." => return None,
            s => parts.push(s),
        }
    }
    Some(parts.join("/"))
}

/// 按序生成候选相对路径：`P` → `P/index.html` → `P.html`
pub fn candidate_paths(rel: &str) -> Vec<String> {
    if rel.is_empty() {
        return vec!["index.html".to_string()];
    }
    vec![
        rel.to_string(),
        format!("{rel}/index.html"),
        format!("{rel}.html"),
    ]
}
```

## Task 3: `protocol.rs` —— 自定义协议处理器

**Step 1: 写实现**

```rust
use crate::webroot::{candidate_paths, normalize_request_path};
use std::path::{Path, PathBuf};
use tauri::http::{Request, Response, StatusCode};

/// 在给定根目录里解析出真实文件与 MIME。找不到返回 `None`。
pub fn resolve_file(root: &Path, request_path: &str) -> Option<(PathBuf, String)> {
    let rel = normalize_request_path(request_path)?;
    for cand in candidate_paths(&rel) {
        let full = root.join(&cand);
        if full.is_file() {
            let mime = mime_guess::from_path(&full)
                .first_or_octet_stream()
                .to_string();
            return Some((full, mime));
        }
    }
    None
}

fn read_response(path: &Path, mime: &str, status: StatusCode) -> Option<Response<Vec<u8>>> {
    let bytes = std::fs::read(path).ok()?;
    Response::builder()
        .status(status)
        .header("Content-Type", mime)
        .header("Cache-Control", "no-cache")
        .body(bytes)
        .ok()
}

/// 从磁盘根目录构造响应。`accept_html` 为真时用 `404.html` 兜底。
pub fn build_response(root: &Path, request_path: &str, accept_html: bool) -> Response<Vec<u8>> {
    if let Some((path, mime)) = resolve_file(root, request_path) {
        if let Some(resp) = read_response(&path, &mime, StatusCode::OK) {
            return resp;
        }
    }
    if accept_html {
        if let Some((path, mime)) = resolve_file(root, "/404.html") {
            if let Some(resp) = read_response(&path, &mime, StatusCode::NOT_FOUND) {
                return resp;
            }
        }
    }
    Response::builder()
        .status(StatusCode::NOT_FOUND)
        .header("Content-Type", "text/plain; charset=utf-8")
        .body(b"Not Found".to_vec())
        .expect("static response must build")
}

fn wants_html(request: &Request<Vec<u8>>) -> bool {
    request
        .headers()
        .get("accept")
        .and_then(|v| v.to_str().ok())
        .map(|v| v.contains("text/html"))
        .unwrap_or(false)
}

/// 还没有任何可用内容包时的兜底页。
/// 正常流程不会出现（首启会先解包种子）；它是「宁可显示一句话也不要白屏」的保险。
fn bootstrap_unavailable() -> Response<Vec<u8>> {
    let body = "<!doctype html><meta charset=\"utf-8\"><title>喵洛阁</title>\
<body style=\"font:16px/1.7 system-ui;padding:2rem;background:#141210;color:#ECE8E1\">\
<h1>正在准备内容</h1><p>请关闭并重新打开应用。</p></body>"
        .as_bytes()
        .to_vec();
    Response::builder()
        .status(StatusCode::SERVICE_UNAVAILABLE)
        .header("Content-Type", "text/html; charset=utf-8")
        .body(body)
        .expect("static response must build")
}

static SEED_TRIED: AtomicBool = AtomicBool::new(false);

/// 取当前 web 根；若没有，则**懒初始化**一次内置种子（解包到 appData）。
///
/// 为什么要这层懒初始化：不依赖 `setup()` 与首个 WebView 请求的先后顺序。
/// 无论哪个先到，第一次请求都会把种子准备好再服务。
fn root_or_seed<R: tauri::Runtime>(app: &tauri::AppHandle<R>) -> Option<PathBuf> {
    if let Some(root) = crate::webroot::current_web_root(app) {
        return Some(root);
    }
    if SEED_TRIED.swap(true, Ordering::SeqCst) {
        return None; // 已经试过，不要每个请求都重试解包
    }
    match crate::content_update::ensure_seed(app) {
        Ok(_) => crate::webroot::current_web_root(app),
        Err(e) => {
            eprintln!("[meowlo] 内置种子初始化失败: {e}");
            None
        }
    }
}

pub fn register<R: tauri::Runtime>(builder: tauri::Builder<R>) -> tauri::Builder<R> {
    builder.register_uri_scheme_protocol("app", |ctx, request| {
        match root_or_seed(ctx.app_handle()) {
            Some(root) => build_response(&root, request.uri().path(), wants_html(&request)),
            None => bootstrap_unavailable(),
        }
    })
}
```

**Step 2: 加 `webroot::current_web_root`**

在 `src-tauri/src/webroot.rs` 追加（这一步把「磁盘根」定下来；内嵌回退在 Task 5 之前先用空的临时目录，Task 5 再补齐内嵌分支）：

```rust
use tauri::Manager;

/// 解析当前应当服务的磁盘目录。返回 `None` 表示还没有任何可用内容包。
///
/// 正常运行时这里总应命中：首启由 `content_update::ensure_seed` 把内置种子
/// （`bundle.resources` 里的 `seed/`）解包成 `<appData>/web/<build>/` 并写入 active.json。
pub fn current_web_root<R: tauri::Runtime>(app: &tauri::AppHandle<R>) -> Option<PathBuf> {
    let state = read_active(app);
    if !is_valid_build(&state.active) {
        return None;
    }
    let base = web_base(app).ok()?;
    let dir = base.join(&state.active);
    if dir.join("index.html").is_file() {
        Some(dir)
    } else {
        None
    }
}

pub fn web_base<R: tauri::Runtime>(app: &tauri::AppHandle<R>) -> Result<PathBuf, String> {
    let dir = app
        .path()
        .app_data_dir()
        .map_err(|e| format!("无法定位应用数据目录: {e}"))?;
    let base = dir.join("web");
    std::fs::create_dir_all(&base).map_err(|e| format!("无法创建 web 目录: {e}"))?;
    Ok(base)
}

pub fn read_active<R: tauri::Runtime>(app: &tauri::AppHandle<R>) -> ActiveState {
    let Ok(base) = web_base(app) else {
        return ActiveState::default();
    };
    let file = base.join(ACTIVE_FILE);
    let Ok(raw) = std::fs::read_to_string(file) else {
        return ActiveState::default();
    };
    serde_json::from_str(&raw).unwrap_or_default()
}

pub fn active_web_dir<R: tauri::Runtime>(app: &tauri::AppHandle<R>) -> Option<PathBuf> {
    let state = read_active(app);
    if !is_valid_build(&state.active) {
        return None;
    }
    let base = web_base(app).ok()?;
    Some(base.join(state.active))
}

/// active.json 指向的 build 是否真的能用来服务页面。
/// 只有「存在 build 且目录里有 index.html」才算可用。
pub fn active_build_is_usable<R: tauri::Runtime>(app: &tauri::AppHandle<R>, build: &str) -> bool {
    if !is_valid_build(build) {
        return false;
    }
    let Ok(base) = web_base(app) else {
        return false;
    };
    base.join(build).join("index.html").is_file()
}
```

> **为什么不用 `app.asset_resolver()` 做内嵌回退**（这里偏离了方案文档 D1 的原写法，理由写清楚）：
> 方案文档原本写的是「web 根找不到时回退到 `app.asset_resolver().get()` 读内嵌资源」。但我们的 WebView 走的是自定义 scheme `app`，而 `asset_resolver()` 的文档说它「默认会推断应用自己的 URL scheme」——当窗口 scheme 不是默认资源 scheme 时，这个推断的键格式与行为**无法在本地验证**（本机没有 Rust，只能靠 CI）。
> 改为：把首启内容做成 **Tauri resource**（`bundle.resources` 里的 `seed/`），首启解包到 appData，此后**永远只从磁盘服务**。好处有三：
> 1. 只用 `bundle.resources` + `BaseDirectory::Resource` 两个长期稳定的 API，零不确定性；
> 2. 种子包与网络更新包**格式完全相同**，走同一套校验/解包/原子切换代码——首启就顺带验证了更新机制；
> 3. 少一条 `asset_resolver` 分支，Rust 面积更小（本项目的核心约束）。
> 代价：首启多一次约 11 MB 的解包（一次性，约 1 秒）。

```rust
const MAX_ARCHIVE_BYTES: u64 = 200 * 1024 * 1024;
const MAX_EXTRACTED_BYTES: u64 = 512 * 1024 * 1024;

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ArchiveInfo {
    pub name: String,
    pub bytes: u64,

#[derive(Debug, Clone, Serialize, Deserialize)]

fn emit_progress<R: Runtime>(app: &AppHandle<R>, phase: &str, received: u64, total: u64) {
    let _ = app.emit(
        "content://progress",
        serde_json::json!({ "phase": phase, "received": received, "total": total }),

fn http_client() -> Result<reqwest::blocking::Client, String> {
    reqwest::blocking::Client::builder()
        .timeout(std::time::Duration::from_secs(120))
        .user_agent("meowlo-app/0.1.0")
        .build()
        .map_err(|e| format!("HTTP 客户端创建失败: {e}"))
}

pub fn fetch_manifest(manifest_url: &str) -> Result<Manifest, String> {
    let client = http_client()?;
    let resp = client
        .get(manifest_url)
        .send()
        .map_err(|e| format!("网络请求失败: {e}"))?;
    if !resp.status().is_success() {
        return Err(format!("服务端返回 {}", resp.status()));
    }
    let manifest: Manifest = resp
        .json()
        .map_err(|e| format!("清单解析失败: {e}"))?;
    validate_manifest(&manifest)?;
    Ok(manifest)
}

pub fn validate_manifest(m: &Manifest) -> Result<(), String> {
    if m.schema != 1 {
        return Err(format!("不支持的清单版本: {}", m.schema));
    }
    if !is_valid_build(&m.build) {
        return Err(format!("非法 build 标识: {}", m.build));
    }
    if m.archive.sha256.len() != 64 || !m.archive.sha256.bytes().all(|b| b.is_ascii_hexdigit()) {
        return Err("压缩包 sha256 格式非法".into());
    }
    if m.archive.bytes == 0 || m.archive.bytes > MAX_ARCHIVE_BYTES {
        return Err("压缩包体积超出允许范围".into());
    }
    if m.files.is_empty() {
        return Err("清单未包含任何文件".into());
    }
    if !m.files.contains_key("index.html") {
        return Err("清单缺少 index.html".into());
    }
    for (rel, hash) in &m.files {
        if rel.starts_with('/') || rel.split('/').any(|s| s == "..") || rel.contains('\\') {
            return Err(format!("清单包含非法路径: {rel}"));
        }
        if hash.len() != 64 {
            return Err(format!("文件 {rel} 的哈希格式非法"));
        }
    }
    Ok(())
}

fn sha256_file(path: &Path) -> Result<String, String> {
    let file = File::open(path).map_err(|e| format!("打开文件失败: {e}"))?;
    let mut reader = BufReader::new(file);
    let mut hasher = Sha256::new();
    let mut buf = [0u8; 64 * 1024];
    loop {
        let n = reader.read(&mut buf).map_err(|e| format!("读取失败: {e}"))?;
        if n == 0 {
            break;
        }
        hasher.update(&buf[..n]);
    }
    Ok(format!("{:x}", hasher.finalize()))
}

fn download_archive<R: Runtime>(
    app: &AppHandle<R>,
    url: &str,
    dest: &Path,
    expected_sha256: &str,
    expected_bytes: u64,
) -> Result<(), String> {
    let client = http_client()?;
    let mut resp = client
        .get(url)
        .send()
        .map_err(|e| format!("下载失败: {e}"))?;
    if !resp.status().is_success() {
        return Err(format!("下载返回 {}", resp.status()));
    }
    let total = resp.content_length().unwrap_or(expected_bytes);
    let mut file = File::create(dest).map_err(|e| format!("创建临时文件失败: {e}"))?;
    let mut hasher = Sha256::new();
    let mut received: u64 = 0;
    let mut buf = [0u8; 64 * 1024];
    loop {
        let n = resp.read(&mut buf).map_err(|e| format!("读取响应失败: {e}"))?;
        if n == 0 {
            break;
        }
        received += n as u64;
        if received > MAX_ARCHIVE_BYTES {
            return Err("压缩包超过体积上限".into());
        }
        hasher.update(&buf[..n]);
        file.write_all(&buf[..n])
            .map_err(|e| format!("写入失败: {e}"))?;
        emit_progress(app, "download", received, total.max(received));
    }
    file.flush().map_err(|e| format!("落盘失败: {e}"))?;
    let actual = format!("{:x}", hasher.finalize());
    if actual != expected_sha256 {
        return Err("压缩包校验失败（哈希不匹配）".into());
    }
    Ok(())
}

fn extract_archive(dest: &Path, archive: &Path, allowed: &BTreeMap<String, String>) -> Result<u64, String> {
    let file = File::open(archive).map_err(|e| format!("打开压缩包失败: {e}"))?;
    let decoder = flate2::read::GzDecoder::new(BufReader::new(file));
    let mut tar = tar::Archive::new(decoder);
    let mut total: u64 = 0;
    for entry in tar.entries().map_err(|e| format!("读取归档失败: {e}"))? {
        let mut entry = entry.map_err(|e| format!("读取条目失败: {e}"))?;
        if !entry.header().entry_type().is_file() {
            continue;
        }
        let raw = entry.path().map_err(|e| format!("条目路径非法: {e}"))?;
        let rel = raw.to_string_lossy().replace('\\', "/");
        let rel = rel.trim_start_matches("./");
        // 白名单：只解压清单里声明的文件，其余一律丢弃（最强的穿越防护）
        if !allowed.contains_key(rel) {
            continue;
        }
        total += entry.size();
        if total > MAX_EXTRACTED_BYTES {
            return Err("解压后体积超过上限".into());
        }
        let out = dest.join(rel);
        if let Some(parent) = out.parent() {
            fs::create_dir_all(parent).map_err(|e| format!("创建目录失败: {e}"))?;
        }
        entry
            .unpack(&out)
            .map_err(|e| format!("解压 {rel} 失败: {e}"))?;
    }
    Ok(total)
}

fn verify_extracted(dir: &Path, files: &BTreeMap<String, String>) -> Result<(), String> {
    for (rel, expected) in files {
        let path = dir.join(rel);
        if !path.is_file() {
            return Err(format!("缺少文件: {rel}"));
        }
        let actual = sha256_file(&path)?;
        if &actual != expected {
            return Err(format!("文件校验失败: {rel}"));
        }
    }
    Ok(())
}

fn write_active<R: Runtime>(app: &AppHandle<R>, active: &str, previous: Option<String>) -> Result<(), String> {
    let base = web_base(app)?;
    let state = ActiveState {
        active: active.to_string(),
        previous,
    };
    let tmp = base.join(format!("{ACTIVE_FILE}.tmp"));
    let body = serde_json::to_vec(&state).map_err(|e| format!("序列化失败: {e}"))?;
    fs::write(&tmp, body).map_err(|e| format!("写入状态失败: {e}"))?;
    fs::rename(&tmp, base.join(ACTIVE_FILE)).map_err(|e| format!("提交状态失败: {e}"))?;
    Ok(())
}

pub fn install<R: Runtime>(app: &AppHandle<R>, manifest_url: &str) -> Result<String, String> {
    let manifest = fetch_manifest(manifest_url)?;
    let base = web_base(app)?;
    let target = base.join(&manifest.build);

    if target.join("index.html").is_file() {
        return Ok(manifest.build);
    }

    let tmp = base.join(format!("{}.tmp", manifest.build));
    if tmp.exists() {
        fs::remove_dir_all(&tmp).map_err(|e| format!("清理临时目录失败: {e}"))?;
    }
    fs::create_dir_all(&tmp).map_err(|e| format!("创建临时目录失败: {e}"))?;

    // 注意：archive 的 URL 由 manifestUrl 同目录推导，保证单一来源
    let archive_url = match manifest_url.rsplit_once('/') {
        Some((dir, _)) => format!("{dir}/{}", manifest.archive.name),
        None => return Err("清单地址非法".into()),
    };
    let archive_path = tmp.join("content.tar.gz");
    if let Err(e) = download_archive(app, &archive_url, &archive_path, &manifest.archive.sha256, manifest.archive.bytes) {
        let _ = fs::remove_dir_all(&tmp);
        return Err(e);
    }

    emit_progress(app, "extract", 0, manifest.file_count);
    if let Err(e) = extract_archive(&tmp, &archive_path, &manifest.files) {
        let _ = fs::remove_dir_all(&tmp);
        return Err(e);
    }
    let _ = fs::remove_file(&archive_path);

    if let Err(e) = verify_extracted(&tmp, &manifest.files) {
        let _ = fs::remove_dir_all(&tmp);
        return Err(e);
    }

    if target.exists() {
        fs::remove_dir_all(&target).map_err(|e| format!("覆盖旧版本失败: {e}"))?;
    }
    fs::rename(&tmp, &target).map_err(|e| format!("切换版本失败: {e}"))?;

    let prev = read_active(app);
    let previous = if prev.active.is_empty() || prev.active == manifest.build {
        prev.previous
    } else {
        Some(prev.active)
    };
    write_active(app, &manifest.build, previous)?;
    Ok(manifest.build)
}

pub fn rollback<R: Runtime>(app: &AppHandle<R>) -> Result<String, String> {
    let state = read_active(app);
    let Some(prev) = state.previous.clone() else {
        return Err("没有可回滚的上一版本".into());
    };
    if !is_valid_build(&prev) {
        return Err("上一版本标识非法".into());
    }
    let base = web_base(app)?;
    let dir = base.join(&prev);
    if !dir.join("index.html").is_file() {
        return Err("上一版本文件已不存在".into());
    }
    write_active(app, &prev, Some(state.active))?;
    Ok(prev)
}

/// 首启/内容缺失时，把 `bundle.resources` 里的内置种子解包成可用的 web 根。
///
/// 种子包与网络更新包**格式完全相同**，因此这条路径同时也验证了更新机制的
/// 校验、解包与原子切换；一旦这里通了，`install` 的正确性也基本有了保障。
pub fn ensure_seed<R: Runtime>(app: &AppHandle<R>) -> Result<Option<String>, String> {
    let state = read_active(app);
    if !state.active.is_empty() && crate::webroot::active_build_is_usable(app, &state.active) {
        return Ok(None);
    }

    let manifest_path = app
        .path()
        .resolve("seed/manifest.json", BaseDirectory::Resource)
        .map_err(|e| format!("找不到内置清单: {e}"))?;
    let raw = fs::read_to_string(&manifest_path).map_err(|e| format!("读取内置清单失败: {e}"))?;
    let manifest: Manifest =
        serde_json::from_str(&raw).map_err(|e| format!("内置清单解析失败: {e}"))?;
    validate_manifest(&manifest)?;

    let base = web_base(app)?;
    let target = base.join(&manifest.build);
    if target.join("index.html").is_file() {
        write_active(app, &manifest.build, None)?;
        return Ok(Some(manifest.build));
    }

    let tmp = base.join(format!("{}.tmp", manifest.build));
    if tmp.exists() {
        fs::remove_dir_all(&tmp).map_err(|e| format!("清理临时目录失败: {e}"))?;
    }
    fs::create_dir_all(&tmp).map_err(|e| format!("创建临时目录失败: {e}"))?;

    let archive = app
        .path()
        .resolve("seed/content.tar.gz", BaseDirectory::Resource)
        .map_err(|e| format!("找不到内置压缩包: {e}"))?;

    if let Err(e) = extract_archive(&tmp, &archive, &manifest.files) {
        let _ = fs::remove_dir_all(&tmp);
        return Err(e);
    }
    if let Err(e) = verify_extracted(&tmp, &manifest.files) {
        let _ = fs::remove_dir_all(&tmp);
        return Err(e);
    }
    if target.exists() {
        fs::remove_dir_all(&target).map_err(|e| format!("覆盖旧目录失败: {e}"))?;
    }
    fs::rename(&tmp, &target).map_err(|e| format!("切换失败: {e}"))?;
    write_active(app, &manifest.build, None)?;
    Ok(Some(manifest.build))
}
```

```rust
            content_rollback
        ]);

        }
    }));

    let builder = protocol::register(builder);

}
```

## Task 6: 内容包生成脚本（TDD：先写失败的测试）

> **本任务遵守的冻结接口契约 v1（不得改动）**
>
> - 内容包格式是 **tar.gz**（不是 zip）。产物：`.output/public/app-dist/manifest.json` + `.output/public/app-dist/content.tar.gz`
> - `manifest.json` 结构：
>   `{"schema":1,"build":"<16 hex>","generatedAt":"<ISO8601>","fileCount":<n>,"totalBytes":<n>,"archive":{"name":"content.tar.gz","bytes":<n>,"sha256":"<64 hex>"},"files":{"<相对路径>":"<64 hex sha256>"}}`
> - `build` = `sha256(按路径排序后拼接的 path\0fileSha256\n).hex.slice(0,16)`
> - tar 条目：相对路径、正斜杠、无前导 `./`、**必须排除 `app-dist/**` 自身**、mtime 固定 `0`
> - gzip 用 `zlib.gzipSync(buf, { level: 9 })`
>
> ⚠️ **格式说明（已与设计方案同步）**：设计文档 `docs/superpowers/specs/2026-11-03-tauri-app-design.md` 最初写的是 **zip**（`content.zip`、zip 整体 sha256、zip-slip），现已按本节改为 **tar.gz**（该文档末尾新增了「§15 实施计划阶段的修订」记录此变更，前述章节里的 `zip` 字样一律按 `tar.gz` 阅读）。改格式的原因是实测本机与 CI 基础镜像都没有 `zip` 命令（只有 `/usr/bin/tar`、`/usr/bin/gzip`），且 Rust 侧 `tar::Archive` 配合清单白名单可彻底防路径穿越。**Rust 章节必须用 `tar` + `flate2` 实现，不要引入 `zip` crate。**

**为什么拆成两个文件（实测依据，别改回去）**

`unrun` 会把脚本重写后执行，入口守卫会**静默失效**。本机 Node `v24.21.0` 实测：

| 运行方式 | `import.meta.main` | `process.argv[1]` |
| --- | --- | --- |
| `node scripts/app/gen-content-bundle.ts` | `true` | 脚本自身路径 |
| `pnpm exec unrun scripts/app/gen-content-bundle.ts` | **`undefined`** | `node_modules/.unrun/<name>.<hash>.mjs`（重写后的临时文件） |
| `node --test`（测试 import 该模块） | `false` | 测试文件路径 |

也就是说，任何 `argv[1] === import.meta.url` / `import.meta.main` 形式的入口判断，在 `pnpm exec unrun` 下都会判为「不是入口」→ **进程退出码 0、没有任何产物**（CI 全绿但内容包没生成，且 app 端表现为"永远检测不到更新"）。

因此：**纯逻辑放 `content-bundle.ts`（可被测试安全 import），CLI 入口放 `gen-content-bundle.ts`（无条件执行，不带任何守卫）**。这样 `node` 与 `pnpm exec unrun` 两种跑法都必然生效。这与仓库既有约定一致（逻辑在 `merge.ts` / `parse.ts`，有副作用的入口在 `index.ts` / `comment-closed.ts`）。

**Files:**
- Create: `scripts/app/content-bundle.ts`（纯逻辑，零依赖，只 import `node:*`）
- Create: `scripts/app/gen-content-bundle.ts`（CLI 入口）
- Test: `scripts/app/gen-content-bundle.test.ts`

```ts
	mtime: number

/**
 * 极简 tar 读取器。它同时充当「这份 tar 符合 ustar 规范」的校验器：
 * 逐条核对 magic 与头校验和，任何一处不合规都会在这里失败。
 */
function readTarEntries(archive: Buffer): TarEntryRead[] {
	const entries: TarEntryRead[] = []
	let offset = 0

	const field = (header: Buffer, start: number, length: number): string =>
		header.subarray(start, start + length).toString('utf8').replaceAll('\0', '').trim()

	while (offset + BLOCK <= archive.byteLength) {
		const header = archive.subarray(offset, offset + BLOCK)
		if (header.every(byte => byte === 0))
			break

		const name = field(header, 0, 100)
		const prefix = field(header, 345, 155)
		assert.equal(header.subarray(257, 263).toString('utf8'), 'ustar\0', `tar magic 不对：${name}`)

		const expectedSum = header.reduce((sum, byte, index) => sum + (index >= 148 && index < 156 ? 0x20 : byte), 0)
		assert.equal(Number.parseInt(field(header, 148, 8), 8), expectedSum, `tar 头校验和不匹配：${name}`)

		const size = Number.parseInt(field(header, 124, 12), 8)
		const mode = Number.parseInt(field(header, 100, 8), 8)
		const mtime = Number.parseInt(field(header, 136, 12), 8)
		offset += BLOCK
		const data = Buffer.from(archive.subarray(offset, offset + size))
		offset += Math.ceil(size / BLOCK) * BLOCK
		entries.push({ path: prefix ? `${prefix}/${name}` : name, data, mode, mtime })
	}

	return entries
}
```

创建 `scripts/app/content-bundle.ts`（完整内容，直接照抄）：

```ts
/**
 * 内容包（tar.gz + manifest.json）的纯逻辑层。
 *
 * 为什么是 tar.gz 而不是 zip：
 * 1. 本机与 CI 基础镜像里都没有 `zip` 命令（实测 `which zip` 无输出，只有 `/usr/bin/tar`、`/usr/bin/gzip`）；
 * 2. Node 侧靠 `node:zlib` + 手写 512 字节 ustar 头就能产出，不需要新增任何依赖（仓库脚本零依赖约定）；
 * 3. Rust 侧 `tar::Archive::unpack` 自带路径穿越防护（`..`、绝对路径直接拒绝），比手写 zip-slip 校验更少出错。
 *
 * 可复现性：tar 条目的 mtime 固定 0、uid/gid 固定 0、mode 固定 0644、路径按字典序排列，
 * 因此内容不变时 `build` 指纹不变。`build` 只由「路径 + 文件 sha256」推出，
 * **不使用压缩包自身的 sha256** —— gzip 字节流会随 zlib 版本/平台变化，拿它当版本标识
 * 会让所有客户端凭空「检测到新内容」。
 *
 * 本文件必须保持无副作用：`gen-content-bundle.test.ts` 会直接 import 它。
 */

import { createHash } from 'node:crypto'
import { existsSync, mkdirSync, readdirSync, readFileSync, rmSync, statSync, writeFileSync } from 'node:fs'
import { join, relative, resolve } from 'node:path'
import { gzipSync } from 'node:zlib'

/** 产物目录名：固定为内容根下的 `app-dist` */
export const APP_DIST_DIR = 'app-dist'
export const MANIFEST_NAME = 'manifest.json'
export const ARCHIVE_NAME = 'content.tar.gz'
export const SCHEMA_VERSION = 1

/** tar 块大小：头与数据都按 512 字节对齐 */
const BLOCK = 512

export interface BundleFile {
	/** 相对内容根的路径：正斜杠分隔、无前导 `./` */
	path: string
	bytes: number
	/** 文件内容的 sha256，64 位小写 hex */
	sha256: string
}

export interface BundleManifest {
	schema: number
	build: string
	generatedAt: string
	fileCount: number
	totalBytes: number
	archive: { name: string, bytes: number, sha256: string }
	files: Record<string, string>
}

export interface TarEntry {
	path: string
	data: Buffer
}

export interface GenerateOptions {
	/** 内容根目录，生产上是 `<repo>/.output/public` */
	root: string
	/** 产物目录，默认 `<root>/app-dist` */
	outDir?: string
	/** 注入当前时间，测试用；默认 `() => new Date()` */
	now?: () => Date
}

export interface GenerateResult {
	manifest: BundleManifest
	archiveBytes: number
	outDir: string
}

function sha256hex(data: Buffer): string {
	return createHash('sha256').update(data).digest('hex')
}

function comparePath(a: string, b: string): number {
	if (a === b)
		return 0
	return a < b ? -1 : 1
}

/**
 * 收集内容根下的所有普通文件并按路径字典序排序。
 *
 * - 相对路径命中 `exclude` 的整棵子树都跳过（默认排除 `app-dist`，防止把正在写的产物打进包里）；
 * - 符号链接直接跳过（`.output` 里若有软链，跟随可能跳出内容根）；
 * - 返回顺序稳定，tar 条目顺序才可复现。
 */
export function collectFiles(root: string, exclude: string[] = [APP_DIST_DIR]): BundleFile[] {
	const files: BundleFile[] = []

	const walk = (dirAbs: string, relDir: string): void => {
		const entries = readdirSync(dirAbs, { withFileTypes: true }).sort((a, b) => comparePath(a.name, b.name))
		for (const entry of entries) {
			const rel = relDir ? `${relDir}/${entry.name}` : entry.name
			if (exclude.includes(rel))
				continue
			if (entry.isSymbolicLink())
				continue
			const abs = join(dirAbs, entry.name)
			if (entry.isDirectory()) {
				walk(abs, rel)
				continue
			}
			if (!entry.isFile())
				continue
			const data = readFileSync(abs)
			files.push({ path: rel, bytes: data.byteLength, sha256: sha256hex(data) })
		}
	}

	walk(resolve(root), '')
	return files.sort((a, b) => comparePath(a.path, b.path))
}

/** 构建指纹：把「路径 + 文件 sha256」按路径排序拼成 `path\0sha256\n`，取 sha256 前 16 位 hex */
export function computeBuild(files: Array<Pick<BundleFile, 'path' | 'sha256'>>): string {
	const hash = createHash('sha256')
	for (const file of [...files].sort((a, b) => comparePath(a.path, b.path)))
		hash.update(`${file.path}\0${file.sha256}\n`)
	return hash.digest('hex').slice(0, 16)
}

/**
 * tar 条目路径必须能安全落地：相对路径、正斜杠、无 `..`、无绝对路径、无前导 `./`。
 *
 * 任何一条不满足都直接抛错，而不是「清洗」：清洗会悄悄改变部署后的 URL，
 * 而这类路径（`..`、绝对路径、含反斜杠的文件名）本来就不该出现在 Nuxt 产物里。
 */
export function assertSafeTarPath(entryPath: string): void {
	if (!entryPath)
		throw new Error('tar 条目路径不能为空')
	if (entryPath.startsWith('/') || /^[A-Za-z]:/.test(entryPath))
		throw new Error(`tar 条目不能是绝对路径：${entryPath}`)
	if (entryPath.includes('\\'))
		throw new Error(`tar 条目必须用正斜杠：${entryPath}`)
	if (entryPath.startsWith('./'))
		throw new Error(`tar 条目不能带前导 ./：${entryPath}`)
	const segments = entryPath.split('/')
	if (segments.some(segment => segment === '' || segment === '.' || segment === '..'))
		throw new Error(`tar 条目含非法路径段（. / .. / 空段）：${entryPath}`)
}

function padOctal(value: number, length: number): string {
	return value.toString(8).padStart(length - 1, '0') + '\0'
}

function writeField(header: Buffer, offset: number, length: number, value: string): void {
	const bytes = Buffer.from(value, 'utf8')
	if (bytes.byteLength > length)
		throw new Error(`tar 头字段溢出（上限 ${length} 字节）：${value}`)
	bytes.copy(header, offset)
}

/**
 * 路径超过 100 字节时按 ustar 规则拆进 prefix 字段（prefix ≤ 155、name ≤ 100）。
 * 绝不截断文件名 —— 截断会让解压出来的路径和 manifest 对不上。
 */
function splitUstarPath(entryPath: string): { prefix: string, name: string } {
	const segments = entryPath.split('/')
	for (let index = segments.length - 1; index > 0; index--) {
		const prefix = segments.slice(0, index).join('/')
		const name = segments.slice(index).join('/')
		if (Buffer.byteLength(prefix, 'utf8') <= 155 && Buffer.byteLength(name, 'utf8') <= 100)
			return { prefix, name }
	}
	throw new Error(`tar 路径超过 ustar 上限（prefix 155 + name 100 字节）：${entryPath}`)
}

/** 生成一个 ustar 头：mtime 固定 0、uid/gid 固定 0、mode 固定 0644、typeflag 普通文件 */
function tarHeader(entryPath: string, size: number): Buffer {
	const header = Buffer.alloc(BLOCK)

	if (Buffer.byteLength(entryPath, 'utf8') <= 100) {
		writeField(header, 0, 100, entryPath)
	} else {
		const split = splitUstarPath(entryPath)
		writeField(header, 0, 100, split.name)
		writeField(header, 345, 155, split.prefix)
	}

	writeField(header, 100, 8, padOctal(0o644, 8))
	writeField(header, 108, 8, padOctal(0, 8))
	writeField(header, 116, 8, padOctal(0, 8))
	writeField(header, 124, 12, padOctal(size, 12))
	writeField(header, 136, 12, padOctal(0, 12))

	// 校验和：先按 8 个空格计算，再写回「6 位八进制 + NUL + 空格」
	writeField(header, 148, 8, '        ')
	writeField(header, 156, 1, '0')
	writeField(header, 257, 6, 'ustar\0')
	writeField(header, 263, 2, '00')
	writeField(header, 265, 32, 'root')
	writeField(header, 297, 32, 'root')

	let sum = 0
	for (const byte of header)
		sum += byte
	writeField(header, 148, 8, `${sum.toString(8).padStart(6, '0')}\0 `)

	return header
}

/** 把若干条目打成未压缩 tar（ustar），结尾两个全零块 */
export function makeTar(entries: TarEntry[]): Buffer {
	const chunks: Buffer[] = []
	for (const entry of entries) {
		assertSafeTarPath(entry.path)
		chunks.push(tarHeader(entry.path, entry.data.byteLength))
		chunks.push(entry.data)
		const padding = (BLOCK - (entry.data.byteLength % BLOCK)) % BLOCK
		if (padding > 0)
			chunks.push(Buffer.alloc(padding))
	}
	chunks.push(Buffer.alloc(BLOCK * 2))
	return Buffer.concat(chunks)
}

/**
 * 生成 `manifest.json` + `content.tar.gz`。
 *
 * 写入前先删掉整个产物目录再重建：上一次残留的旧文件不会混进部署目录，脚本本身幂等。
 * 内容根里一个文件都没有时直接报错 —— 空内容包会让所有客户端「更新」到空白页面。
 */
export function generateContentBundle(options: GenerateOptions): GenerateResult {
	const root = resolve(options.root)
	if (!existsSync(root) || !statSync(root).isDirectory())
		throw new Error(`内容根目录不存在或不是目录：${root}（先跑 pnpm generate）`)

	const outDir = resolve(options.outDir ?? join(root, APP_DIST_DIR))
	const now = options.now ?? (() => new Date())

	// 产物目录若落在内容根内部，必须排除，否则会把上一次的产物打进这一次的包里
	const exclude = [APP_DIST_DIR]
	const relativeOut = relative(root, outDir).split('\\').join('/')
	if (relativeOut && relativeOut !== '..' && !relativeOut.startsWith('../'))
		exclude.push(relativeOut)

	const files = collectFiles(root, exclude)
	if (files.length === 0)
		throw new Error(`内容根里没有任何文件：${root}（先跑 pnpm generate）`)

	const entries: TarEntry[] = files.map(file => ({ path: file.path, data: readFileSync(join(root, file.path)) }))
	const archive = gzipSync(makeTar(entries), { level: 9 })

	const manifest: BundleManifest = {
		schema: SCHEMA_VERSION,
		build: computeBuild(files),
		generatedAt: now().toISOString(),
		fileCount: files.length,
		totalBytes: files.reduce((sum, file) => sum + file.bytes, 0),
		archive: {
			name: ARCHIVE_NAME,
			bytes: archive.byteLength,
			sha256: sha256hex(archive),
		},
		files: Object.fromEntries(files.map(file => [file.path, file.sha256])),
	}

	rmSync(outDir, { recursive: true, force: true })
	mkdirSync(outDir, { recursive: true })
	writeFileSync(join(outDir, ARCHIVE_NAME), archive)
	writeFileSync(join(outDir, MANIFEST_NAME), `${JSON.stringify(manifest, null, '\t')}\n`)

	return { manifest, archiveBytes: archive.byteLength, outDir }
}
```

```ts
	}
```

```ts
	{ svg: 'icon-android-bg.svg', png: 'app-icon-android-bg.png' },
	{ svg: 'icon-android-mono.svg', png: 'app-icon-android-mono.png' },
]

async function render(svg: string, png: string): Promise<void> {
	const source = readFileSync(join(svgDir, svg))
	const out = join(iconDir, png)
	const info = await sharp(source).resize(size, size).png({ compressionLevel: 9 }).toFile(out)
	if (info.width !== size || info.height !== size)
		throw new Error(`${png} 尺寸不对：${info.width}×${info.height}，应为 ${size}×${size}`)
	console.log(`  ${png}  ${info.width}×${info.height}  ${info.size} bytes  ← svg/${svg}`)
}

mkdirSync(iconDir, { recursive: true })
for (const target of targets)
	await render(target.svg, target.png)

if (process.argv.includes('--preview')) {
	mkdirSync(previewDir, { recursive: true })
	for (const px of [16, 24, 32, 48, 64]) {
		// 从 1024 成品图缩小，而不是用 16px 重新渲染 SVG：
		// 系统与 tauri icon 走的都是「大图缩小」这条路，校核必须看同一路径的结果
		const out = join(previewDir, `icon-${px}.png`)
		const info = await sharp(readFileSync(join(iconDir, 'app-icon.png'))).resize(px, px).png({ compressionLevel: 9 }).toFile(out)
		console.log(`  preview icon-${px}.png  ${info.width}×${info.height}  ${info.size} bytes`)
	}
	console.log(`目视校核图目录：${relative(rootDir, previewDir).split('\\').join('/')}`)
}
```

**`android_fg_scale` 到底作用于哪一层（源码级结论，别猜）**

- `ic_launcher_foreground.png` = `android_fg` 直接 `resize_exact` 到 108/162/216/324/432（mdpi→xxxhdpi），**完全不经过 `android_fg_scale`**；

### 本任务必须逐字遵守的冻结接口契约 v1

```
前端检测：const isApp = typeof window !== 'undefined' && '__TAURI__' in window
命令调用：window.__TAURI__.core.invoke('<命令>', { ... })

app_status()             → { embeddedBuild: string, activeBuild: string,
                             source: 'embedded'|'downloaded', pendingBuild: string|null,
                             platform: 'windows'|'macos'|'linux'|'android'|'ios',
                             lastError: string|null }
content_check(manifestUrl: string) → { state:'up-to-date', build }
                                   | { state:'update-available', build, bytes, generatedAt }
                                   | { state:'offline' }
                                   | { state:'error', message }
content_install(manifestUrl: string) → { ok:true, build } | { ok:false, message }
content_rollback()       → { ok: boolean, build: string }
事件 content://progress  → { phase:'download'|'extract', received:number, total:number }
```

三处工程取舍（写进代码注释里，避免后人踩）：

1. **`window.__TAURI__` 需要 `tauri.conf.json` 打开 `app.withGlobalTauri: true`**，否则全局对象根本不存在。这是本章对 CI / 配置章节的**硬前置依赖**（见交付说明里的汇报项）。
2. **事件订阅**：契约冻结了事件名与 payload，但没规定订阅 API。全局 API 下唯一零依赖的写法是 `window.__TAURI__.event.listen('content://progress', handler)`（返回 `Promise<unlisten>`），它需要 capability 里有 `core:event:allow-listen`。无法绕开，也不能引第三方插件（D8）。
3. **`manifestUrl` 参数名用 camelCase**：Tauri v2 默认把 JS 侧 camelCase 键映射到 Rust 的 snake_case 参数（`manifest_url`），所以 `core.invoke('content_check', { manifestUrl })` 是正确写法，不要改成 `manifest_url`。

**Step 1: 写契约类型**

```ts
import type { Ref } from 'vue'

/**
 * app（Tauri v2）前端契约 —— 与 Rust 命令面「冻结接口契约 v1」逐字对应。
 *
 * 命令签名与返回结构由 Rust 侧冻结，本文件只做类型映射，不要改字段名：
 * - app_status()            → AppStatus
 * - content_check(url)      → ContentCheckResult
 * - content_install(url)    → ContentInstallResult
 * - content_rollback()      → ContentRollbackResult
 * - 事件 content://progress → ContentProgress
 */

export type AppPlatform = 'android' | 'ios' | 'linux' | 'macos' | 'windows'

export interface AppStatus {
	/** 二进制内嵌的内容版本号（16 位 hex） */
	embeddedBuild: string
	/** 当前实际生效的版本号 */
	activeBuild: string
	/** 当前生效的是内嵌内容还是下载内容 */
	source: 'downloaded' | 'embedded'
	/** 已下载待生效的版本；无则为 null */
	pendingBuild: string | null
	platform: AppPlatform
	/** 上次内容包操作留下的错误；无则为 null */
	lastError: string | null
}

export type ContentCheckResult =
	| { state: 'up-to-date', build: string }
	| { state: 'update-available', build: string, bytes: number, generatedAt: string }
	| { state: 'offline' }
	| { state: 'error', message: string }

export type ContentInstallResult =
	| { ok: true, build: string }
	| { ok: false, message: string }

export interface ContentRollbackResult {
	ok: boolean
	build: string
}

export interface ContentProgress {
	phase: 'download' | 'extract'
	received: number
	total: number
}

/** UI 用来决定状态点颜色的提示级别 */
export type AppNoticeKind = 'error' | 'offline' | 'success'

/** `useAppBridge()` 的返回类型；字段都是 ref，组件里可直接解构 */
export interface AppBridge {
	/** 冻结契约的检测结果，浏览器下恒为 false */
	isApp: boolean
	/** isApp && blogConfig.app.enable */
	enabled: boolean
	/** app_status 的结果；未读到为 null */
	status: Ref<AppStatus | null>
	/** 最近一次 content_check 的结果；未检查过为 null */
	check: Ref<ContentCheckResult | null>
	/** 下载 / 解压进度；空闲为 null */
	progress: Ref<ContentProgress | null>
	/** 要显示给用户的提示文案；null 表示不打扰 */
	notice: Ref<string | null>
	noticeKind: Ref<AppNoticeKind | null>
	hasUpdate: Ref<boolean>
	installing: Ref<boolean>
	/** 内容包损坏，需要用户回滚（由 AppBootError 呈现） */
	bootBroken: Ref<boolean>
	refreshStatus: () => Promise<void>
	/** manual = 用户主动检查；只有主动检查才允许把断网 / 失败说出来 */
	checkContent: (manual?: boolean) => Promise<ContentCheckResult | null>
	installContent: () => Promise<void>
	rollbackContent: () => Promise<ContentRollbackResult | null>
}

/**
 * Tauri 全局 API（`app.withGlobalTauri: true` 时注入）。
 * 只声明本项目用到的两个命名空间：core.invoke 与 event.listen。
 */
interface TauriGlobal {
	core: {
		invoke: <T>(command: string, args?: Record<string, unknown>) => Promise<T>
	}
	event: {
		listen: <T>(event: string, handler: (event: { payload: T }) => void) => Promise<() => void>
	}
}

declare global {
	interface Window {
		__TAURI__?: TauriGlobal
	}
}

declare module '#app' {
	interface NuxtApp {
		/** 只在 Tauri WebView 的客户端插件里注入；SSR 预渲染与浏览器下不存在 */

	}
}

declare module 'vue' {

	}
```

**Step 3: 写桥插件**

创建 `app/plugins/app-bridge.client.ts`：

```ts
import type {
	AppBridge,
	AppNoticeKind,
	AppStatus,
	ContentCheckResult,
	ContentInstallResult,
	ContentProgress,
	ContentRollbackResult,
} from '~/types/app'
import blogConfig from '~~/blog.config'
import { createDetachedAppBridge } from '~/composables/useAppBridge'

/**
 * app 桥：检测是否运行在 Tauri WebView 内，并封装内容包命令。
 *
 * 冻结接口契约 v1（不要改）：
 * - 检测：`typeof window !== 'undefined' && '__TAURI__' in window`
 * - 调用：`window.__TAURI__.core.invoke('<命令>', { ... })`
 * - 进度：事件 `content://progress`
 *
 * 文件名以 `.client.ts` 结尾：SSR / 静态预渲染阶段根本不执行，
 * 所以浏览器访问站点时既不会渲染 app-only UI，也不会发出任何命令调用。
 */
export default defineNuxtPlugin((nuxtApp) => {
	// ⚠️ 冻结接口契约 v1：检测语句原样保留，不要改写成其它探测方式
	const isApp = typeof window !== 'undefined' && '__TAURI__' in window
	const tauri = typeof window === 'undefined' ? undefined : window.__TAURI__
	const config = blogConfig.app

	if (!isApp || !tauri) {
		nuxtApp.provide('appBridge', createDetachedAppBridge())
		return
	}

	const { core, event } = tauri
	/** 内容清单地址：由 contentBase + manifestPath 拼出后交给 Rust */
	const manifestUrl = `${config.contentBase}${config.manifestPath}`

	const status = ref<AppStatus | null>(null)
	const check = ref<ContentCheckResult | null>(null)
	const progress = ref<ContentProgress | null>(null)
	const notice = ref<string | null>(null)
	const noticeKind = ref<AppNoticeKind | null>(null)
	const hasUpdate = ref(false)
	const installing = ref(false)

	let unlisten: (() => void) | null = null

	function setNotice(text: string | null, kind: AppNoticeKind | null) {
		notice.value = text
		noticeKind.value = kind
	}

	function toMessage(error: unknown) {
		return error instanceof Error ? error.message : String(error)
	}

	/** 读取 app_status：内嵌 / 生效版本、平台与上次错误 */
	async function refreshStatus() {
		try {
			status.value = await core.invoke<AppStatus>('app_status')
		}
		catch {
			// 读不到状态不影响阅读，UI 会退回「正在读取内容状态…」
			status.value = null
		}
	}

	/**
	 * 检查更新。
	 *
	 * @param manual 只有用户主动点「检查更新」时才允许把断网 / 失败说出来；
	 *               启动时的自动检查一律静默（硬要求：断网不打扰）。
	 */
	async function checkContent(manual = false): Promise<ContentCheckResult | null> {
		if (!config.enable)
			return null

		setNotice(null, null)

		let result: ContentCheckResult
		try {
			result = await core.invoke<ContentCheckResult>('content_check', { manifestUrl })
		}
		catch (error) {
			// invoke 本身抛错（命令未注册 / IPC 异常）也当成一次失败的检查，不往外抛
			result = { state: 'error', message: toMessage(error) }
		}
		check.value = result

		if (result.state === 'update-available') {
			hasUpdate.value = true
			return result
		}

		hasUpdate.value = false
		if (result.state === 'offline') {
			if (manual)
				setNotice('当前没有网络连接，已下载的内容仍可正常阅读。', 'offline')
		}
		else if (result.state === 'error' && manual) {
			setNotice(`检查更新失败：${result.message}`, 'error')
		}
		return result
	}

	/** 下载并应用新内容；失败只解释，不阻断当前内容 */
	async function installContent() {
		if (installing.value || !config.enable)
			return

		installing.value = true
		setNotice(null, null)
		progress.value = null

		try {
			const result = await core.invoke<ContentInstallResult>('content_install', { manifestUrl })
			if (result.ok) {
				hasUpdate.value = false
				// Rust 切换 web 根后会自己重载 webview；前端不再 reload，避免双重跳转
				setNotice(`内容已更新到 ${result.build}，正在应用…`, 'success')
			}
			else {
				setNotice(`更新失败：${result.message}。当前内容不受影响，可稍后重试。`, 'error')
			}
		}
		catch (error) {
			setNotice(`更新失败：${toMessage(error)}。当前内容不受影响，可稍后重试。`, 'error')
		}
		finally {
			installing.value = false
			progress.value = null
		}
	}

	/** 回滚到上一版本（内容包损坏时由 AppBootError 调用） */
	async function rollbackContent(): Promise<ContentRollbackResult | null> {
		try {
			return await core.invoke<ContentRollbackResult>('content_rollback')
		}
		catch {
			return null
		}
	}

	/** 订阅下载 / 解压进度 */
	async function subscribeProgress() {
		try {
			unlisten = await event.listen<ContentProgress>('content://progress', ({ payload }) => {
				progress.value = payload
			})
		}
		catch {
			// 事件通道不可用（例如 capability 缺 core:event 权限）时只是没有进度条，更新本身照常
		}
	}
	void subscribeProgress()

	/**
	 * 内容包损坏判定。
	 *
	 * 契约 v1 只给了 `lastError: string|null`，没有定义它的语义，这里取最保守的读法：
	 * **当前生效的是「下载」内容，且 Rust 记录了错误** —— 内嵌内容不可能「下载损坏」。
	 * 若 Rust 侧日后细化了语义，只需要改这一个函数。
	 */
	const bootBroken = computed(() =>
		status.value !== null
		&& status.value.lastError !== null
		&& status.value.source === 'downloaded',
	)
```

**Step 2: 写临时 mock 插件（验证用，不进交付）**

创建 `app/plugins/00-app-bridge-mock.client.ts`。文件名前缀 `00-` 是刻意的：Nuxt 按文件名字母序执行插件，必须让它**先于** `app-bridge.client.ts` 运行，否则桥已经用「没有 `__TAURI__`」的结论初始化完了，mock 再多也没用。

```ts
/**
 * ⚠️ 临时视觉 / 交互校核用 mock —— 不属于交付物，Task 14 必须删除。
 *
 * 用法：pnpm dev 后访问
 *   http://localhost:3000/__app-preview?appmock=idle
 *   http://localhost:3000/__app-preview?appmock=update
 *   http://localhost:3000/__app-preview?appmock=offline
 *   http://localhost:3000/__app-preview?appmock=error
 *   http://localhost:3000/__app-preview?appmock=broken
 */
export default defineNuxtPlugin(() => {
	if (!import.meta.dev)
		return
	const scenario = new URLSearchParams(window.location.search).get('appmock')
	if (!scenario)
		return

	const progressHandlers: Array<(event: { payload: unknown }) => void> = []
	const currentBuild = 'a1b2c3d4e5f60718'
	const nextBuild = 'ffee001122334455'

	Object.defineProperty(window, '__TAURI__', {
		configurable: true,
		value: {
			core: {
				async invoke(command: string) {
					switch (command) {
						case 'app_status':
							return {
								embeddedBuild: currentBuild,
								activeBuild: scenario === 'broken' ? nextBuild : currentBuild,
								source: scenario === 'broken' ? 'downloaded' : 'embedded',
								pendingBuild: null,
								platform: 'windows',
								lastError: scenario === 'broken' ? 'content pack sha256 mismatch: index.html' : null,
							}
						case 'content_check':
							if (scenario === 'offline')
								return { state: 'offline' }
							if (scenario === 'error')
								return { state: 'error', message: 'manifest.json 404 Not Found' }
							if (scenario === 'update' || scenario === 'progress')
								return { state: 'update-available', build: nextBuild, bytes: 3412345, generatedAt: '2026-11-03T03:00:00Z' }
							return { state: 'up-to-date', build: currentBuild }
						case 'content_install': {
							const total = 3412345
							let received = 0
							const timer = window.setInterval(() => {
								received = Math.min(total, received + Math.round(total / 8))
								for (const handler of progressHandlers)
									handler({ payload: { phase: 'download', received, total } })
								if (received >= total) {
									window.clearInterval(timer)
									for (const handler of progressHandlers)
										handler({ payload: { phase: 'extract', received, total } })
								}
							}, 400)
							await new Promise(resolve => window.setTimeout(resolve, 4000))
							return { ok: true, build: nextBuild }
						}
						case 'content_rollback':
							return { ok: true, build: currentBuild }
						default:
							throw new Error(`unknown command: ${command}`)
					}
				},
			},
			event: {
				async listen(_event: string, handler: (event: { payload: unknown }) => void) {
					progressHandlers.push(handler)
					return () => {
						const index = progressHandlers.indexOf(handler)
						if (index >= 0)
							progressHandlers.splice(index, 1)
					}
				},
			},
		},
	})
})
```

```vue
const { isApp, bootBroken, status, rollbackContent } = bridge

const rolling = ref(false)
/** 回滚成功后的目标版本；非 null 时页面切到「成功」分支 */
const rolledBackBuild = ref<string | null>(null)
const failure = ref<string | null>(null)

const activeBuild = computed(() => status.value?.activeBuild ?? '未知版本')
const detail = computed(() => status.value?.lastError ?? '内容包没有通过校验')

async function rollback() {
	if (rolling.value)
		return
	rolling.value = true
	failure.value = null

	const result = await rollbackContent()
	rolling.value = false

	if (!result) {
		failure.value = '回滚命令没有响应。可以点「重新加载页面」再试一次；若一直失败，请卸载后重新安装。'

	}

}

	window.location.reload()
}
```

## Task 14: 挂到根组件 + 浏览器全量验收

**Files:**

- Delete（临时文件）: `blog/app/pages/__app-preview.vue`
- Delete（临时文件）: `blog/app/plugins/00-app-bridge-mock.client.ts`

### 为什么挂在 `app.vue` 而不是 `layouts/default.vue`

`layouts/default.vue` 只服务默认布局；`/go` 用的是 safego 专用布局，换布局时那个 `v-if` 里的 UI 会整体消失。`app.vue` 是根组件，包住所有布局，才是「任何页面都在」的正确位置。

### 为什么必须显式 import

`app/components/app/AppStatusBar.vue` 在 Nuxt 默认的 `components` 规则下会被加目录前缀，注册名是 `AppAppStatusBar`（`nuxt.config.ts` 里只有 `'~/components'` 一条默认规则）。模板里写 `<AppStatusBar />` 会解析失败并打印「Failed to resolve component」。显式 import 比改 `nuxt.config.ts` 的 `components` 数组（还要处理 `@keep-sorted` 顺序）更小、更稳。

### 为什么必须包 `<ClientOnly>`

静态产物的 HTML 是构建时预渲染的，那一刻 `window` 不存在，`isApp` 只能是 `false`；客户端在 Tauri 里水合时 `isApp` 变成 `true`。若直接渲染就会水合不匹配。`<ClientOnly>` 保证这段 DOM 只可能出现在客户端，浏览器下则永远不会出现。

```vue
 * 内联箭头函数每次渲染都是新引用，会让 NuxtPage 重启加载条；旧实现用 `v-once` 规避，

 * 页面就会渲染成空白。改成模块级稳定函数后不再需要 `v-once`，两者都能成立。
 */

// app-only UI 的数据源。非 Tauri 环境（含 SSR 预渲染）拿到的是 isApp=false 的空实现。
const appBridge = useAppBridge()

<template>
	<NuxtLayout>
		<!-- pageKey 现在是稳定引用，这里不需要 v-once，路由仍由 NuxtPage 内部更新。 -->
		<NuxtPage :page-key="contentPageKey" />

	<!--
		app-only UI。ClientOnly 是必须的：静态产物在服务端预渲染时 `__TAURI__` 不存在，

</template>
```

## Task 15: `src-tauri/tauri.conf.json` —— 身份 / 窗口 / CSP / bundle targets

**为什么这个 Task 排在所有 Rust 任务之前（前置关系，必须写进 PR 描述）**

`tauri-build` 是 `src-tauri/build.rs` 里的第一行，它在 **`cargo check` 阶段**（不是打包阶段）就会读取并反序列化 `src-tauri/tauri.conf.json`：

- 文件不存在 → `tauri-build` 直接 panic，**整个 Rust 骨架一行都编译不过**；
- 字段名写错（比如把 v2 的 `devUrl` 写成 v1 的 `devPath`）→ 反序列化失败，报错点在 build script 里，极难看出是配置文件的问题；
- 所以本 Task 是 Lead 章节 Task 1（Rust 骨架）的**硬前置**：先合这个文件，`cargo check` 才有意义。

同时它是三条跨章节契约的锚点：

**Step 5: 核对五个容易写错、且不会报错的点**

逐条对照，全部为「是」才继续：

1. `build.devUrl` 是 v2 的键名（v1 叫 `devPath`）。写错的后果：`tauri dev` 找不到前端。
2. `build.frontendDist` 是 `"stub"`，指向 `src-tauri/stub/`（一个**提交进 git** 的极简占位页）。**不能**写官方指引里的 `"../dist"`：本仓库的 `dist` 未被 git 跟踪、只是本地软链接 `dist -> .output/public`，CI 上根本不存在。
   站点内容**不再**通过 `frontendDist` 分发，而是走 `bundle.resources` 里的种子包 `seed/`（见下条说明）。这样应用二进进制里只带一份内容，不会既内嵌 11 MB 站点又塞一份种子。
3. `bundle.resources` 的两项路径**相对 `tauri.conf.json` 所在目录**（即 `src-tauri/`），所以落地位置是 `src-tauri/seed/manifest.json` 与 `src-tauri/seed/content.tar.gz`。这两个文件由 Task 16 在 `tauri build` 之前生成，**不要提交进 git**（Task 9 已有忽略规则）。
4. `app.windows[0].url` 是 `"app://localhost/"`：它不是 http/https，因此 Tauri 会解析成 `WebviewUrl::CustomProtocol`（见 `tauri-utils` 的 `WebviewUrl` 反序列化实现）；Windows / Android 上 Tauri 会把 `app://localhost/` 映射为 `http://app.localhost/`，macOS / Linux / iOS 上仍是 `app://localhost/`。协议处理器必须按绝对路径解析（设计方案 D1）。
5. `bundle.targets` 是一个**混合列表**，这是安全的：`tauri-bundler` 的 `Settings::package_types()` 会按当前目标 OS 过滤——Windows 只会得到 `nsis`，Linux 得到 `appimage`，macOS 得到 `dmg`（`.app` 会被内部构建后清理）。所以**不需要**平台专用配置文件，也不会因为「列了别的平台的 target」而报错。

**Step 6: 记下 v1 的一处主动裁剪与一个必须靠首轮 CI 确认的点**

- **`deb` 目标已从 v1 移除（主动决策，不是遗漏）**：`tauri-bundler` 的 `bundle/linux/debian.rs` 用 `heck::AsKebabCase(productName)` 生成 `Package:`。CJK 字符在 heck 里算「无大小写的字母」，不会被剥离，因此产品名「喵洛阁」极可能产出 `Package: 喵洛阁`；而 Debian 策略要求包名只能是 `[a-z0-9][a-z0-9+.-]+`，`dpkg -i` 会拒绝安装。更麻烦的是 `bundle.linux.deb` 里**没有**包名覆写字段（只有 `depends`/`recommends`/`section`/`priority`/`files`/`desktopTemplate`/脚本），所以没有「改个配置就好」的选项。
  → 与其发一个装不上的包，不如 v1 只发 AppImage。等确认上游是否补了覆写字段、或把 `productName` 改成 ASCII 再评估。**这条不需要在 CI 里试错，已经按最坏情况规避。**
- **`stub` 目录必须存在且被提交**：`tauri-codegen` 在 `frontendDist` 不存在时会报错（不只是告警）。`src-tauri/stub/index.html` 是我们自己提交的占位页，所以 `cargo check` job 不再需要额外创建目录（见 Task 16）。
- **CSP 是否真的生效（未证实）**：`app.security.csp` 由 Tauri 在**它自己服务的资源路径**上注入。我们的窗口加载的是自己注册的 `app://` 协议，HTML 由 `protocol.rs` 自己读盘返回——如果 Tauri 不对用户注册的协议做 CSP 注入，那么这份 CSP 就是空转。Task 18 Step 8 要求在 Windows 实测时用 DevTools 确认：若 Console 完全没有 CSP 相关行为（或注入的 CSP 不在响应里），就需要由 Lead 章节的 `protocol.rs` 在 HTML 响应头里自己写同一条 CSP。**本文档只登记这个契约，不改 `protocol.rs`。**

## Task 17: 修改 `deploy-cloudflare-pages.yml` —— 站点部署链路增加内容包生成步骤

> ⚠️ **这是对线上部署工作流的修改（中等风险 / 设计 R7）。动手前先读下面两段。**

**风险是什么**

`deploy-cloudflare-pages.yml` 是 `main` 每次推送都会跑的**生产部署**工作流，还被 `fcircle.yml` 通过 `workflow_call` 复用。改错它的直接后果是「博客发不出新文章」。

**回滚方式（两个档次，都为一分钟级操作）**

| 档次 | 操作 | 效果 |
| --- | --- | --- |
| 精确回滚（首选） | `git revert <本 Task 的 commit sha>` 并推送 | 工作流回到改动前；下次部署不再生成 `app-dist` |
| 手动禁用（应急） | 在 GitHub 网页上删除/注释掉 `Generate app content bundle` 这一个 step，或把整段 `run` 换成 `echo skip` | 同上，但仓库历史里不干净 |

**回滚后的行为（必须知道，不是"无影响"）**：回滚后新的 Cloudflare Pages 部署里**没有** `/app-dist/`，所以：

- `GET https://blog.kemeow.top/app-dist/manifest.json` → **404**；
- app 端表现为**检测不到更新**（站点功能完全不受损，只是内容包停在最后一次成功部署的那份，或者干脆没有）；
- 因此 Nuxt 侧 `content_check` 契约必须把 404/非 JSON 归到 `{ state:'error' }` 或 `{ state:'offline' }` 并静默处理，**不能**把它当成崩溃。这条属于 Task 4 的契约，本 Task 只登记。

**精确插入点与上下文**

目标文件：`E:/github_maochenyu_me/blog/blog/.github/workflows/deploy-cloudflare-pages.yml`（现 106 行）。

```yaml
      - 'LICENSE*'

      ref:

  cancel-in-progress: false

        uses: actions/checkout@v4
        with:
          ref: ${{ inputs.ref || github.sha }}

      - name: Setup pnpm
        uses: pnpm/action-setup@v4

            exit 1
          fi
          du -sh .output/public

      # 站点侧生成 app 热更新用的内容包：.output/public/app-dist/{manifest.json,content.tar.gz}
      # 随后随整站一起部署，app 从 https://blog.kemeow.top/app-dist/manifest.json 拉取。
      # 只在部署链路生成；app 构建链路（build-app.yml）不生成，保持二进制干净。
      # 失败即中断部署（宁可红、不要静默产出坏的清单）；回滚 = revert 本提交或删掉本 step。
      - name: Generate app content bundle
        timeout-minutes: 10
        run: |
          set -euo pipefail
          pnpm exec unrun scripts/app/gen-content-bundle.ts
          echo "::group::app-dist"
          ls -la .output/public/app-dist
          head -c 400 .output/public/app-dist/manifest.json; echo
          echo "::endgroup::"
      # ─────────────────────────────────────────────────────────────────────

      # 使用 wrangler 直接命令：先幂等创建项目（忽略“已存在”），再部署。
      # 任何非“已存在”的错误都会打印完整 stderr 并中断，便于排查 token/权限/名称问题。
      - name: Deploy to Cloudflare Pages (auto-create project)
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}

          set -euo pipefail

          echo "::group::Ensure Pages project"
          set +e

          create_code=$?

              exit "$create_code"
            fi
          fi
          echo "::endgroup::"

          echo "::group::Deploy"
          pnpm dlx wrangler@${{ env.WRANGLER_VERSION }} pages deploy .output/public \
            --project-name="$CF_PAGES_PROJECT_NAME" \
            --branch="${GITHUB_REF_NAME:-main}" \
            --commit-dirty=true
          echo "::endgroup::"
```

## 附 B：Lead 合并时的修正记录（2026-11-03）

本章由 Lead 在合并四个起草分片后统一裁决。**以下是最终决定，前面章节里若有与之一致的旧表述，以本节为准。**

### 已解决的决策

| # | 议题 | 最终决定 |
| --- | --- | --- |
| 1 | 内容包格式 | **`tar.gz`**，不是 `zip`。理由：Bash 环境下无 `zip` 命令（实测只有 `tar`/`gzip`）；Node 用 `node:zlib` 即可生成、零新增依赖；Rust 侧 `tar::Archive` + 清单白名单可彻底防路径穿越。设计方案 §2/§5.3/D2/D5/§8.3/S14 里写的 `content.zip` **全部按 `content.tar.gz` 阅读**（spec 已同步修正）。 |
| 2 | 内嵌资源回退方式 | **改为 seed resource**，不再用 `app.asset_resolver()`。原方案的写法有一个真实缺口：`current_web_root` 回退到一个从未被填充的目录，首启会全 404；而 `asset_resolver` 在自定义 scheme 下的键格式无法本地验证。改法：首启内容做成 `bundle.resources` 里的 `seed/`，解包到 appData 后**永远只从磁盘服务**。代价是首启多一次约 1 秒的解包；收益是零不确定 API，且种子与网络更新走**同一套**校验/解包/原子切换代码——首启就顺带验证了更新机制。 |
| 3 | `frontendDist` | 改为 **`stub`**（指向提交进 git 的 `src-tauri/stub/index.html`）。站点内容不再经 `frontendDist` 分发，应用二进制里只保留一份内容。 |
| 4 | 种子生成时机 | 挂在 `beforeBuildCommand` 上：`pnpm generate && pnpm exec unrun scripts/app/gen-content-bundle.ts --out src-tauri/seed`。脚本已有 `--out` 参数，部署链路仍用默认输出到 `.output/public/app-dist/`。 |
| 5 | `deb` 目标 | **v1 移除**，Linux 只发 AppImage。`tauri-bundler` 用 `heck::AsKebabCase(productName)` 生成 `Package:`，CJK 产品名会产出 `dpkg -i` 拒绝的包名，且 `bundle.linux.deb` 无覆写字段。宁可少一个包，也不发一个装不上的包。 |
| 6 | `keepPreviousBuilds` | **从 `blog.config.ts` 删除**。冻结契约里四个命令没有传参入口，这个键是悬空配置；Rust 固定保留 1 个历史版本，正好够回滚。宁可没有，也不要一个不生效的键。 |
| 7 | `app_status().lastError` 语义 | **已定义**：`active.json` 指向某个 build、但该目录缺少 `index.html` 时为非空。这是 AppBootError「回到上一版本」的唯一触发条件。 |
| 8 | 事件订阅权限 | `src-tauri/capabilities/default.json` 由 **Task 5** 提供；`core:default` 已包含 `core:event:default`（含 `allow-listen`），无需额外条目。 |
| 9 | `@tauri-apps/cli` 依赖 | 由 **Task 19** 正式声明，并删除 Task 16 里的 CI 兜底。 |
| 10 | `unrun` 入口守卫 | 内容包脚本**必须**保持「`content-bundle.ts` 纯逻辑 + `gen-content-bundle.ts` 无守卫入口」的拆分。实测 `pnpm exec unrun <script>` 会重写到临时 `.mjs`，使 `import.meta.main` 恒为 `undefined`——合并回一个文件会让 CI 全绿而内容包永不生成。**Review 时不要把它们合并。** |
| 11 | 移动端 init 与图标 | 保持 Task 16 的 `hashFiles` 守卫：`gen/` 已提交时 CI 不再 `init`，否则每次 CI 都会把已提交的移动端图标覆盖回 Tauri 默认图标（静默回归）。 |
| 12 | CI 并行策略 | 保持 `needs: check`：三个构建 job 都等 `check` 绿了再跑，严格执行「编译错误最先暴露」。 |

### 原始不一致清单（保留备查，已逐条处理）

1. **内容包格式：`zip` vs `tar.gz`。** 设计方案 `docs/superpowers/specs/2026-11-03-tauri-app-design.md` 的 §2 术语表、§5 架构图、D2、D5、§8.3 仍写 `content.zip` / `zip`；而冻结接口契约（Task 3）与本章节 Task 17 按 **`content.tar.gz`**（`zlib.gzipSync`，level 9）。**以 tar.gz 为准**，建议把设计文档里那几处 `zip` 一并改成 `tar.gz`，否则两个实现者会各写一半。本章节按 tar.gz 写。
2. **`deb` 包名风险。** Lead 明确要求 Linux 加 `"deb"`/`"appimage"`，本章节照写；但 `tauri-bundler` 无 deb 包名覆写字段，CJK `productName` 很可能产出非法 `Package:`。处置见 Task 15 Step 5 与 Task 18 Step 6（实测后可能删掉 `"deb"`）。
3. **`@tauri-apps/cli` 未声明为依赖。** 本仓库 devDependencies 里没有它，而 Task 16 的四个 job 全都需要它。本章节用 workflow 内 `pnpm add --save-dev` 兜底；永久方案（加 catalog + devDependencies）需要有人认领 `pnpm-workspace.yaml` 与 `blog/package.json`。
4. **`gen/android`、`gen/apple` 的 init 时机。** 冻结事实要求「先 `tauri android init` / `tauri ios init` 生成 `gen/`，再跑 `tauri icon`」——这是**本地一次性顺序**（图标由 Task 3 产出并随仓库提交）。因此 Task 16 的 CI 只在 `gen/` 缺失时才 init（`hashFiles` 守卫），避免每次 CI 都把已提交的移动端图标覆盖回 Tauri 默认图标。若 Lead 希望 CI 每次都 init，请同时把「图标由 CI 重新生成」并入 Task 16，否则会出现「图标被悄悄换掉」的回归。
