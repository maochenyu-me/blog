## Task 1：生成并提交 PWA 图标全套

**目标**：从 `public/img/avatar/avatar.webp`（256×256）生成 192 / 512 / maskable-512 / apple-touch-180，提交进仓库。

**为什么一次性生成而不是每次构建生成**：见设计稿 T1（避开 Nuxt 4 `app/public` 路径问题、确定性强、图标是静态资源）。

**步骤**

1. 用**一次性**命令生成（不加入项目依赖）：
   - 工具：`@vite-pwa/assets-generator`，通过 `pnpx` 调用
   - 预置：`minimal-2023`（产出 favicon / pwa-64 / pwa-192 / pwa-512 / maskable-512 / apple-touch-180）
   - 源图：`public/img/avatar/avatar.webp`
   - **产物落到临时目录**，人工挑选后再放进仓库，避免覆盖现有 `public/favicon.ico`
2. 把需要的产物放入 `public/img/pwa/`：
   - `icon-192.png`、`icon-512.png`、`maskable-512.png`
   - `public/apple-touch-icon.png`（iOS 默认查找路径，放根目录）
3. **不要动** `public/favicon.ico`（`blogConfig.favicon` 引用中，且 `/favicon.ico` 有 308 重定向规则）。

**验证**

- 用 node 读取每个 PNG 的 IHDR，断言尺寸精确等于 192/512/512/180
- maskable 版本**四周留安全区**：把图像缩到中心 80% 区域后检查边缘像素为填充色（用 node 读 PNG 像素或断言生成器预设行为 + 目视截图）
- 每个文件体积合理（PNG 单张 < 100KB）
- `git status` 只新增 `public/img/pwa/*` 与 `public/apple-touch-icon.png`

**完成标准**：4 张图标就位且尺寸/安全区验证通过，未触碰 `public/favicon.ico`。

## Task 2：manifest 补全 + head 注入（修复缺口 A）

**目标**：让浏览器能发现 manifest，并补齐 iOS 所需 meta。

**文件**

- `nuxt.config.ts`（`pwa.manifest` 与 `app.head`）
- `app/app.vue`（挂 `<NuxtPwaManifest />`）

**步骤**

1. `pwa.manifest` 补 `icons`：
   ```ts
   icons: [
     { src: '/img/pwa/icon-192.png', sizes: '192x192', type: 'image/png' },
     { src: '/img/pwa/icon-512.png', sizes: '512x512', type: 'image/png' },
     { src: '/img/pwa/maskable-512.png', sizes: '512x512', type: 'image/png', purpose: 'maskable' },
   ],
   ```
   `background_color` 用 `#FFFFFF`（亮色模式 `--c-bg` = `hsl(220deg 0% 100%)` = 纯白，已核实）；`theme_color` 用 `#1A5EFF`。
2. `app.head.meta` 增补（保持 `@keep-sorted` 顺序）：
   - `apple-mobile-web-app-capable: yes`
   - `apple-mobile-web-app-title: 喵洛阁`
   - `apple-mobile-web-app-status-bar-style: default`
   - `theme-color` 两条：`media: '(prefers-color-scheme: light)'` 与 `'dark'`，值取亮/暗模式底色
3. `app/app.vue` 模板内加 `<NuxtPwaManifest />`（放在根级、`ClientOnly` 之外）
4. 扩写 `themeColorScript`：用户改主色时同步更新 `theme-color` meta（保持既有 try/catch 与正则校验风格）

**验证**

- `pnpm generate` 成功
- 产物 HTML grep 到 `<link rel="manifest"`、`apple-mobile-web-app-capable`、`theme-color`
- `.output/public/manifest.webmanifest` 内容含 3 条 icons 与正确 name/start_url/display
- `pnpm exec eslint nuxt.config.ts app/app.vue` 零报错

**完成标准**：manifest 被 HTML 引用、iOS meta 齐备、图标在 manifest 中声明。

## Task 4：Workbox 缓存分层完整化（修复缺口 B）

**目标**：按设计稿 §5.3 落地完整策略。

**文件**：`nuxt.config.ts`（`pwa.workbox`）

**步骤**

1. `globPatterns` **补 `wasm`**（修复缺口 B，否则离线搜索坏）：
   ```ts
   globPatterns: ['**/*.{js,css,html,json,xml,txt,svg,ico,wasm,woff,woff2}'],
   ```
2. `globIgnores` 保持排除 `**/img/**`、`**/music/**`、`_ipx/**`
3. `navigateFallback` 指向 T3 实测出的 `/offline` 路径
4. `runtimeCaching` 增加四组：
   - 图片 `/_ipx/**`、`/img/**` → `CacheFirst`，`expiration: { maxEntries: 200, maxAgeSeconds: 2592000 }`
   - 音频 `/music/**` → `CacheFirst` + `RangeRequestsPlugin`，`maxEntries: 30`
   - 站外样式字体 `s4.zstatic.net`、`fonts.bytedance.com` → `StaleWhileRevalidate`，`maxEntries: 30`
   - 第三方 API `ecoku.518339.xyz`、`tg-api.518339.xyz`、`hot-api.liiiu.cn`、`meting.081531.xyz`、`netease.518339.xyz` → `NetworkOnly`
5. 保持 `registerType: 'autoUpdate'`

**验证**

- `pnpm generate` 成功，构建日志打印新的 precache 条目数（应比 366 多出 wasm 等，体积增加约 844KB）
- `grep -o 'url:"[^"]*wasm[^"]*"' .output/public/sw.js` **命中**（缺口 B 已修）
- sw.js 内含四组 runtime caching 的匹配规则（按域名/路径 grep）
- 预缓存中 `/img/`、`/music/`、`_ipx/` 条目仍为 0

**完成标准**：wasm 进预缓存、四组运行时策略生效、媒体仍不占预缓存。

## Task 5：iOS 一次性引导

**目标**：iOS 上补足原生入口缺失（评审 D4）。

**文件**

- 新建 `app/components/blog/PwaIosHint.vue`
- `app/layouts/default.vue`（挂载）

**步骤**

1. 出现条件（**同时满足**）：
   - iOS/iPadOS：`/iPad|iPhone|iPod/.test(UA)` **或**（`navigator.platform === 'MacIntel' && navigator.maxTouchPoints > 1`）——后者覆盖 iPadOS 伪装成 macOS 的情况
   - 未安装：`!(window.navigator.standalone) && !matchMedia('(display-mode: standalone)').matches`
   - 未关闭过：`localStorage.getItem(<flag>)` 为空
2. 交互：底部一次性提示条，文案说明「点分享按钮 → 添加到主屏幕」，带关闭按钮；关闭写入 flag
3. `onMounted` 后才判定（避免 SSR/预渲染阶段误判），组件用 `<ClientOnly>` 或在模板上做客户端判断
4. 视觉复用站点毛玻璃与主题变量，断点用实际数值

**验证**

- 浏览器 UA 模拟 iPhone + 非 standalone → 提示出现
- 点关闭 → `localStorage` flag 写入 → 刷新不再出现
- 模拟 `display-mode: standalone`（DevTools 有对应模拟）→ 不出现
- 桌面浏览器与安卓 UA → 不出现
- `pnpm exec eslint` 零报错；桌面/移动截图各一张

**完成标准**：三种条件判定正确，关闭后不复现，其他端零影响。

## 执行顺序与依赖

```
T1 图标 ──→ T2 manifest+head ──→ T3 /offline ──→ T4 workbox ──→ T9 验收 ──→ T10 收尾
                                    │                  ▲
T5 iOS 引导 ──┐                     └──────────────────┘
T6 离线降级 ──┼──→ （独立，可并行）        T7 headers ──┘
T8 关于页文案 ┘
```

- T1 → T2 有依赖（manifest 需要图标路径）
- T3 → T4 有依赖（T4 的 `navigateFallback` 需要 T3 实测出的路径）
- T5 / T6 / T7 / T8 相互独立，可并行
- T9 必须等 T1–T8 全部完成

## 风险与回滚

- 每个 Task 独立提交，出问题可单独回退
- T4 若 `navigateFallback` 配错会导致离线导航异常 → 有 T9 的 S5 兜住
- 若 T9 发现预缓存体积不可接受，回退手段是收窄 `globPatterns`（把大 chunk 移出预缓存、改运行时缓存）
